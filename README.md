# Land Radar

React + PostgreSQL workspace for tracking LED auction properties locally at **http://127.0.0.1:5080**.

## เปิดใช้งาน

ดับเบิลคลิก `Start.cmd` และเปิด http://127.0.0.1:5080 เก็บหน้าต่างโปรแกรมไว้ระหว่างใช้งาน กด Ctrl+C เพื่อหยุด หลังแก้ frontend ใช้ `Start.cmd --build` โดยหยุดโปรแกรมเดิมก่อน

เครื่องนี้ใช้ฐานข้อมูล `led_radar` / schema `land_radar` รหัสอยู่ใน `server/appsettings.Local.json` ซึ่งไม่รวมใน Git ภาพอยู่ใน `server/data/evidence/` ให้สำรองฐานข้อมูลและภาพคู่กัน

## สองชุดตัวกรอง

- **ตั้งค่าซิงค์:** เลือก checkbox จังหวัดและอำเภอได้หลายรายการ บันทึกใน PostgreSQL ค่าเริ่มต้นคือเชียงใหม่ / เมืองเชียงใหม่ ซิงค์ทุกประเภททรัพย์ ทุกช่วงราคา และทุกขนาดพื้นที่ที่ต้นทางส่งมา ข้ามแถวสีแดงตามคำขอเดิม
- **สำรวจทรัพย์:** กรองข้อมูลในฐานข้อมูลตามราคา พื้นที่ (ไร่) ประเภททรัพย์ จังหวัด อำเภอ ดาว 0–5 บุ๊กมาร์ก สถานะที่ผู้ใช้กรอก และข้อความค้นหา การกรองไม่เปลี่ยนขอบเขตซิงค์ จำตัวกรองแสดงผลไว้ในเบราว์เซอร์

ห้องชุดแสดงพื้นที่เป็นตารางเมตร ตัวกรองพื้นที่แปลงเป็นหน่วยเดียวกันก่อนเปรียบเทียบ (1 ไร่ = 1,600 ตารางเมตร) พื้นที่ห้องชุดไม่ใช่ขนาดที่ดินของโครงการ

รายชื่อ 77 จังหวัดและรหัสอำเภอของต้นทางเก็บเป็น reference ในโครงการ รวมรหัสเดิม/ชื่อซ้ำที่ต้นทางยังมี โดยแสดงรหัสกำกับชื่อซ้ำ หน้าตั้งค่าจึงไม่ต้องอ่านฟอร์มต้นทางทุกครั้ง

## การซิงค์

ระบบตรวจรอบทุกนาทีขณะโปรแกรมเปิด ค่าเริ่มต้นสัปดาห์ละครั้ง (168 ชั่วโมง) เปลี่ยนเป็นทุก 1, 6 หรือ 24 ชั่วโมงได้ รอบถัดไปนับจากงานล่าสุดจบ เปิดเครื่องใหม่แล้วตรวจรอบที่ค้าง ปุ่ม **ซิงค์ด้วยตนเอง** เริ่มรอบทันที และ **ค้นพิกัดที่ยังขาด** ทำเฉพาะ LandsMaps

**CAPTCHA ยังต้องให้คนกรอก:** เมื่อถึงขอบเขตที่จะค้น ระบบเตรียมฟอร์มและแสดงรหัสด้านบนพร้อมสถานะ `waiting_captcha` หลังยืนยันจะอ่านทุกหน้าและบันทึกอัตโนมัติ แล้วขอรหัสสำหรับขอบเขตถัดไปเมื่อจำเป็น ไม่แก้ CAPTCHA หรือเลี่ยงการยืนยันอัตโนมัติ จึงไม่รับรองการซิงค์แบบไม่ต้องมีคนอยู่เลย

ข้อผิดพลาดจากงานเบื้องหลังถูกเก็บในฐานข้อมูลและแสดงด้านบนจนกดรับทราบ ไม่บันทึกว่าซิงค์สำเร็จหากอ่านหน้าไม่ครบ งานหยุดกลางคันเก็บรายการที่อ่านแล้วไว้ งานใหม่ upsert ทับรายการเดิม

รหัสประจำรายการคำนวณจากชุดขาย ลำดับทรัพย์ เลขคดี และจังหวัด ไม่ใช้ราคา หมายเลขหน้า หรือตำแหน่งแถว จึงอัปเดตราคา/รายละเอียดโดยไม่สร้างรายการซ้ำในชุดขายเดิม รายการที่เคยอ่านสำเร็จและข้อมูลแถวต้นทางไม่เปลี่ยนจะไม่เปิดหน้ารายละเอียดหรือดาวน์โหลดรูปซ้ำ หากราคา/ข้อมูลแถวเปลี่ยนจะอ่านและอัปเดตทับ การเปลี่ยนวันประมูลเฉพาะในหน้ารายละเอียดโดยแถวไม่เปลี่ยนอาจไม่ถูกตรวจพบภายใต้นโยบายข้ามรายการซ้ำนี้ หากต้นทางสร้างชุดขายใหม่ถือเป็นประกาศคนละรายการ เก็บเวลาพบครั้งแรก ล่าสุด และจำนวนรอบที่พบเพื่อให้ตรวจย้อนหลังได้

## บันทึกส่วนตัวและอายุข้อมูล

ใน PROPERTY DETAILS ใส่บุ๊กมาร์ก ดาว 0–5 คอมเมนต์ สถานะ “ยังอยู่ในสถานะประมูล / จบแล้ว” และช่อง “ห้ามลบอัตโนมัติ” แล้วกดบันทึก ข้อมูลส่วนนี้แยกจากข้อมูลต้นทางและไม่ถูกซิงค์ทับ

ลบทรัพย์เมื่อ **วันที่ปัจจุบันในไทยเกินวันประมูลสุดท้าย + 1 เดือนปฏิทิน** เช่น นัดสุดท้าย 08/04/2570 เก็บถึง 08/05/2570 และลบตั้งแต่ 09/05/2570 วันปลายเดือนปรับเป็นวันสุดท้ายของเดือนถัดไปหากไม่มีวันเดียวกัน

ข้อยกเว้นเริ่มต้นมีเฉพาะช่อง “ห้ามลบอัตโนมัติ” ตามที่ผู้ใช้เลือก บุ๊กมาร์ก ดาว และคอมเมนต์อย่างเดียวไม่ยกเว้นการลบ สามารถเปลี่ยนนโยบายในหน้าตั้งค่าได้ ช่องห้ามลบมีผลเสมอ ข้อมูลที่ไม่มีวันประมูลหรืออ่านวันที่ไม่สมบูรณ์จะไม่ถูกลบโดยเดา

ระบบลบแถวข้อมูลและเข้าคิวลบรูปที่ไม่มีทรัพย์อื่นใช้อ้างอิง หากลบไฟล์ไม่สำเร็จจะแจ้ง error และลองใหม่ เก็บเพียงรหัส hash และเวลาที่เคยพบใน `sync_seen` เพื่อป้องกันสับสนเรื่องประวัติซิงค์ ไม่มีข้อความประกาศหรือภาพในตารางนี้

## รายละเอียดและหลักฐาน

- ประเภททรัพย์ ลำดับทรัพย์ เลขคดี โจทก์ โฉนด เนื้อที่ ราคาประเมิน วันประมูล และภาพประกาศ
- ภาพประกาศเลื่อนหน้าเพื่อโหลดรูป รอรูปทุกภาพโหลดและ decode เสร็จ แล้วหน่วงเพิ่ม 3 วินาทีก่อนแคป หากรอเกิน 45 วินาทีแล้วยังไม่ครบ จะแจ้งเตือนและลองใหม่ในรอบถัดไป ภาพจากรุ่นเดิมจะถูกเก็บใหม่หนึ่งครั้งโดยไม่สร้างทรัพย์ซ้ำ
- ราคาเต็มและตัวเลขลด 10%, 20%, 30% เป็นการคำนวณเพื่อเปรียบเทียบ ไม่ใช่การยืนยันราคาเริ่มประมูล
- วันที่ผ่านมาเป็นสีเทา วันข้างหน้าเป็นสีเขียว และนัดถัดไปเน้นสีเข้ม
- LandsMaps เก็บพิกัดจากผลค้นหาจังหวัด/อำเภอ/โฉนด ตรวจชื่อพื้นที่ให้ตรง รอภาพพื้นหลังแล้วหน่วงเพิ่ม เก็บภาพพร้อม popup และภาพที่ปิด popup แล้ว หากภาพไม่ครบแสดงคำเตือนและค้นซ้ำได้
- แผนที่ขยายเต็มพื้นที่หน้าจอได้ ปักเฉพาะพิกัดจริง ไม่ใช้จุดศูนย์กลางอำเภอแทน

## Facebook

ปุ่มใน PROPERTY DETAILS อ่านเพจสาธารณะ https://web.facebook.com/ledcm2 โดยไม่ใช้บัญชี ค้นคำว่า “ขายทอดตลาดทรัพย์” และวันประมูล เลือกช่วงวันตรงกันหรือก่อน/หลัง 3, 7, 14 วัน รองรับช่องว่างและเลขไทย

เก็บ **ภาพเต็ม** พร้อม URL โพสต์และเหตุผลการจับคู่ ยังไม่มี OCR ยืนยันเลขคดีหรือตัดแถวอัตโนมัติ และไม่เปลี่ยนสถานะประมูลที่ผู้ใช้กรอก จำกัดการเลื่อน 20 รอบ เลือกสูงสุด 6 โพสต์ที่ตรงที่สุด และสูงสุด 60 รูปต่ออัลบั้ม ขอบเขตนี้ไม่รับรองการค้นย้อนหลังครบทุกโพสต์ หาก Facebook จำกัดการเข้าถึงหรือภาพไม่ครบ จะแสดงข้อจำกัดไว้

## เทคโนโลยีและตรวจสอบ

React + TypeScript + Leaflet / OpenStreetMap, Node.js + Express + Playwright, PostgreSQL Backend แยก domain, application, infrastructure, presentation ตาม [architecture](docs/architecture.md)

ใช้ Node.js เนื่องจาก Windows Application Control เครื่องนี้บล็อก .NET DLL ที่คอมไพล์เอง และใช้ Rollup WebAssembly โดยไม่ปิดระบบความปลอดภัย

```powershell
cd server
npm test
npm run format:check
cd ../client
npm run build
```

ใช้ `npm run format` ใน server ก่อน commit การทดสอบ live จากโฟลเดอร์โครงการ: `node tests/smoke-lands.mjs` และ `node tests/smoke-catalog-db.mjs` การทดสอบ DB เพิ่ม fixture ID ใหม่ชั่วคราวและลบทิ้งเมื่อจบ

## เครื่องใหม่

ติดตั้ง Node.js LTS, PostgreSQL และสร้างฐานข้อมูล led_radar แล้วตั้งไฟล์ local ที่ไม่ลง Git:

```json
{
  "ConnectionStrings": {
    "Postgres": "Host=localhost;Port=5432;Database=led_radar;Username=postgres;Password=YOUR_PASSWORD"
  }
}
```

รัน `Start.cmd --build` โปรแกรมฟังเฉพาะ 127.0.0.1 ไม่เหมาะสำหรับเปิดสาธารณะโดยไม่มีระบบบัญชีผู้ใช้

## ล้างชุดข้อมูล

คำสั่ง `node scripts/reset-local-data.mjs --confirm-reset` ใช้เฉพาะเมื่อได้รับอนุญาตให้ลบข้อมูล ต้องปิดแอปก่อน คำสั่งล้างข้อมูล Land Radar และรูปหลักฐานทั้งหมด รวมการตั้งค่า/บันทึกส่วนตัว ไม่กระทบฐานข้อมูลอื่น คำสั่งนี้ไม่ถูกเรียกอัตโนมัติเมื่อเปิดโปรแกรม
